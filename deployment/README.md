# Deployment

The node is a single static binary plus a data directory. There is no container
image and no cloud dependency — nothing here requires a network service, a
database, or root.

> **Development/testnet only.** Before exposing this to a real network, read
> [../BLOCKERS.md](../BLOCKERS.md): the RPC is unauthenticated for reads, the P2P
> transport is unencrypted, and releases are unsigned.

## Single node

```bash
go build -o bin/znd ./cmd/znoded
export ZND_PASSWORD='...'                 # or use --password-file
bin/znd init --home /var/lib/znet
bin/znd run  --home /var/lib/znet \
             --genesis /etc/znet/genesis.json \
             --p2p 0.0.0.0:26656 \
             --rpc 127.0.0.1:26657 \
             --moniker node-eu-1 \
             --log-level info
```

Key points:

- `--rpc` defaults to `127.0.0.1`. Keep it there unless a reverse proxy fronts it.
- `ZND_RPC_TOKEN` enables bearer auth for the only write method,
  `z_sendRawTransaction`.
- `znd init` refuses to overwrite an existing `validator.key.json`. Back that file
  up; it is the validator identity.
- The node needs no `--genesis` after the first block is stored: it recovers the
  chain id from `data/blocks.log`.

## Multi-validator network

`scripts/testnet.sh` is the reference topology: N processes on loopback, node 0
as the seed, real genesis generated by `zcli devnet`. Read it before writing a
production launcher — it is ~150 lines and contains no magic.

## systemd unit (single node)

```ini
[Unit]
Description=Z Network node
After=network-online.target

[Service]
Type=simple
User=znet
Environment=ZND_RPC_TOKEN=
EnvironmentFile=/etc/znet/env
ExecStart=/usr/local/bin/znd run --home /var/lib/znet --genesis /etc/znet/genesis.json --rpc 127.0.0.1:26657 --p2p 0.0.0.0:26656 --moniker node-1
Restart=on-failure
RestartSec=3
LimitNOFILE=65536

# Hardening: the node needs only its home directory.
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/var/lib/znet
ProtectKernelTunables=true
ProtectControlGroups=true
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX
MemoryMax=2G

[Install]
WantedBy=multi-user.target
```

`/etc/znet/env` (mode 0600):

```
ZND_PASSWORD=<validator keystore password>
ZND_RPC_TOKEN=<long random token, only if RPC is exposed to a trusted host>
```

Note: `ZND_PASSWORD` is only read by `znd init`; a running node needs the
`--password-file` or the same environment variable to open the keystore. Keep the
file mode 0600 and owned by the service user.

## Reverse proxy for the RPC

If the RPC must be reachable from another host, terminate TLS and rate limit at a
proxy. Example with nginx:

```nginx
server {
    listen 443 ssl http2;
    server_name rpc.example.net;
    ssl_certificate     /etc/ssl/rpc.crt;
    ssl_certificate_key /etc/ssl/rpc.key;

    location / {
        limit_req zone=rpc burst=20 nodelay;
        proxy_pass http://127.0.0.1:26657;
        proxy_set_header Host $host;
        proxy_read_timeout 35s;
    }
    location /explorer/ {
        proxy_pass http://127.0.0.1:26657;
    }
}
```

`limit_req_zone $binary_remote_addr zone=rpc:10m rate=20r/s;` goes in the `http`
block. The node itself has no rate limiting (BLOCKERS B-008).

## Monitoring

Scrape `/metrics` (Prometheus text format) and probe `/healthz`.

```yaml
scrape_configs:
  - job_name: znetwork
    static_configs:
      - targets: ["127.0.0.1:26657"]
```

Alert on:

| Signal | Condition | Meaning |
|---|---|---|
| `znet_height` | unchanged for > 30 s | liveness problem |
| `znet_rounds_advanced_total` | rate > 0 sustained | proposer or network trouble |
| `znet_peer_count` | 0 | isolated node |
| `znet_mempool_size` | growing without blocks | stalled execution |
| `/healthz` | non-200 | process unhealthy |

## Backups

Back up `validator.key.json` (encrypted, 0600) and, for a fast restore, the
newest `data/states/*.state` plus `data/blocks.log`. The chain can always be
rebuilt from `blocks.log`; the index is derived and can be deleted.

There is no hot-backup tool. Copy while the node is stopped, or copy
`blocks.log` plus the newest snapshot and accept replay from that point.

## What is missing for production

- Authenticated transport (B-003) — a deployment over the public internet is not
  safe today.
- Signed releases (B-014).
- A state pruning policy — `data/states/` grows one file per block.
- An external audit (B-002).
